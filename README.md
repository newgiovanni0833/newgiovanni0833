##  Sobre mim

Sou economista e trabalho no ponto em que três disciplinas se encontram:

- **Economia** dá o critério: o que vale a pena medir, quanto custa errar e qual é o retorno esperado.
- **Dados** dão a evidência: pipelines, modelos dimensionais e painéis que a diretoria realmente usa.
- **Governança (LGPD)** dá a segurança: saber quais dados pessoais existem, por onde circulam, quem acessa e por quanto tempo ficam guardados.

Hoje atuo como **Analista Pleno de Dados Estratégicos no SENAR-MT (Sistema Famato)**, onde mantenho um portfólio de **mais de 35 dashboards em Power BI**, construo rotinas de ETL em Python e SQL Server e conduzo a **governança de dados pessoais** da instituição. Em paralelo, desenvolvo **estudos de viabilidade econômico-financeira** e **soluções web** para pequenos negócios.

Antes disso passei por controladoria em logística, pesquisa aplicada para a indústria e crédito bancário. Essa trajetória explica por que meus painéis sempre terminam em uma pergunta de negócio, e não em um gráfico.

##  Repositórios de dados: como eu estruturo

Um repositório de dados só é útil se for **confiável, reproduzível e seguro**. Sigo o mesmo roteiro em todos os projetos:

```text
 Fontes                Ingestão               Modelagem            Consumo
┌──────────────┐    ┌───────────────┐    ┌────────────────┐    ┌──────────────┐
│ ERPs e APIs  │    │ Python ETL    │    │ SQL Server     │    │ Power BI     │
│ CSV / Excel  │ ─▶ │ chunks        │ ─▶ │ staging + MERGE│ ─▶ │ Star Schema  │
│ sistemas web │    │ checkpoint    │    │ dimensões/fatos│    │ acesso por   │
└──────────────┘    └───────────────┘    └────────────────┘    │ perfil       │
                                                               └──────────────┘
        └──────────── Governança: inventário de dados · ROPA · glossário ────────────┘
```

1. **Mapear antes de carregar.** Todo campo de origem é confrontado com o destino (presente, derivado, ausente ou sem tabela). O gap vira backlog de modelagem.
2. **Carga incremental e idempotente.** Staging, `MERGE` e checkpoint: rodar duas vezes não duplica nada.
3. **Qualidade registrada.** Datas implausíveis, registros órfãos e linhas desalinhadas vão para um log, em vez de sumir em silêncio.
4. **Documentação como entrega.** Dicionário de dados, diagrama de relacionamentos e regra de cálculo de cada medida.
5. **Privacidade desde o desenho.** Dados pessoais identificados no inventário, finalidade e prazo de guarda definidos, acesso por perfil e termo de responsabilidade para quem consome.
6. **Segredos fora do código.** Credenciais em variáveis de ambiente ou cofre, nunca em script ou repositório.
